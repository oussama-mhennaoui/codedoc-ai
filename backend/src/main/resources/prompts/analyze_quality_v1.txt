EXIGENCES D'ANALYSE :
1. Score de qualité global (score_global) :
   - Un entier entre 0 et 100 représentant la maintenabilité, la lisibilité et la robustesse du code.
   - 90-100 : Excellent code, propre, testable et conforme aux standards.
   - 75-89 : Bon code avec quelques améliorations mineures possibles.
   - 50-74 : Qualité moyenne, présence de code smells notables ou dette technique modérée.
   - 0-49 : Mauvaise qualité, code critique, dette technique élevée ou violations majeures.

2. Détection des code smells (code_smells) :
   - Détecte les mauvaises pratiques : fonctions trop longues (Long Method), classes trop volumineuses (God Class/Large Class), duplication de code, envie de fonctionnalités (Feature Envy), couplage excessif, paramètres trop nombreux, variables magiques (Magic Numbers), gestion des exceptions insuffisante ou muette, code mort.
   - Pour chaque code smell, spécifie :
     - type : Nom du code smell (ex: "Long Method", "Violation SRP", "Duplicate Logic", "Magic Number", "Primitive Obsession").
     - fichier : Le nom du fichier analysé ("{{fileName}}").
     - ligne : Le numéro de ligne approximatif ou précis où se situe le problème dans le code source fourni (entier positif >= 1).
     - gravite : Exactement l'une des 3 valeurs : "critique", "moyen", "faible".
     - description : Explication claire et concise du problème détecté.
     - suggestion_refactoring : Action concrète et priorisée pour corriger le smell (ex: "Extraire les lignes 45-70 dans une méthode privée validatePayload()").
     - code_original : Extrait exact du code source concerné (1 à 15 lignes max) illustrant le problème avant correction.
     - code_refactorise : Extrait de code refactorisé propre et prêt à l'emploi remplaçant le code problématique en appliquant les bonnes pratiques.

3. Respect des principes SOLID (respect_solid) :
   - Évalue le respect des principes :
     - srp : Single Responsibility Principle (score et analyse).
     - ocp : Open/Closed Principle (score et analyse).
     - lsp : Liskov Substitution Principle (score et analyse).
     - isp : Interface Segregation Principle (score et analyse).
     - dip : Dependency Inversion Principle (score et analyse).
     - resume : Synthèse globale du respect des principes SOLID.

4. Duplication de code (duplication) :
   - pourcentage_estime : Estimation du pourcentage de code dupliqué ou redondant (0 à 100).
   - details : Description des blocs redondants ou répétitifs s'il y en a.

5. Complexité (complexite) :
   - score_cyclomatique : Estimation de la complexité cyclomatique globale (1 à 50+).
   - score_cognitif : Estimation de la charge cognitive pour un développeur (1 à 50+).
   - details : Analyse des structures imbriquées, boucles, branchements conditionnels multiples.

6. Dette technique (dette_technique) :
   - estimation_minutes : Estimation réaliste du temps de refactoring en minutes (ex: 30, 60, 180).
   - niveau : "faible", "moyen", "eleve", ou "critique".
   - resume : Synthèse de la dette technique.
